Pour permettre à l'agent d'assurance externe (Sanlam / Courtier) de collaborer sans compromettre les données confidentielles de la flotte GoCab :

  • Accès Isolé : Accès uniquement à la page Assurance & Gestion des Sinistres.
  • Masquage Strict : Pas d'accès aux Rappels Réparations, ni aux dettes chauffeurs, ni aux colonnes de trésorerie interne.
  • Chronomètre Arrêt Sinistre : Le compteur de jours démarre dès la première apparition sur la page Assurance (pas la date globale d'achat véhicule).

/// Schéma de données principal d'un sinistre
model AccidentClaim {
  id              String    @id @default(uuid())
  vehicle_id      String
  driver_id       String?
  driver_name     String?
  driver_phone    String?
  severity        String?   // HARD (Lourde) | SOFT (Légère)
  fault           String?   // DRIVER | THIRD_PARTY
  timeline_step   String    @default("NEW_ACCIDENT")
  step_updated_at DateTime  @default(now())
  comments        String?   // JSON: InsuranceDossierInfo & Notes
  documents       String?   // JSON: Array<AccidentDocument>
  created_at      DateTime  @default(now())
  updated_at      DateTime  @updatedAt

  vehicle         Vehicle   @relation(fields: [vehicle_id], references: [id])
  driver          DriverProfile? @relation(...)
}
Persistance durable sur LibSQL/Turso avec réplication SQLite locale instantanée.

🧱 Structures JSON Extensibles

Pour préserver une flexibilité maximale face aux exigences évolutives des compagnies d'assurance sans migration SQL lourde :

InsuranceDossierInfo : N° sinistre, police, nom expert, montant devis, franchise, statut paiement, et état notification WhatsApp du gestionnaire.

AccidentDocument : Métadonnées complètes du fichier (nom, taille, mimeType, catégorie CONSTAT/DEVIS/PHOTOS, date et auteur de téléversement).

StepValidationItem : Historique complet des horodatages et signatures de chaque étape validée.

🔒 Intégrité & Cohérence des Données

  • Validation stricte des payloads via schémas Zod.
  • Normalisation automatique des étapes rétrocompatibles (CAR_IN_GARAGE ➔ GARAGE_DEVIS).
  • Indexation sur vehicle_id, timeline_step et created_at pour des requêtes en < 15ms.
